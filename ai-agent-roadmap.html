🤖 AI Agent 知识地图

每天一个知识点 · 理论 + 实战 · 说人话

🔥 Day 1-4
DAY 1

Agent 到底是什么？

从"会说话的 AI"到"会干活的 AI"——最基础的概念分水岭
❶Agent ≠ 套壳聊天框
LLM 只会回答问题，Agent 有"手和脚"可以主动干活。

你用的 ChatGPT、Claude、文心一言——都是 大模型（LLM）。只能回答问题、生成文本，不会主动干活。

Agent = LLM + 工具 + 自主决策
简单说：LLM 是脑子，Agent 是长了手和脚的脑子。
❷Agent 的三件套
感知→思考→行动，三个环节构成 Agent 的最小工作循环。

👁️ 感知 → 🧠 思考 → 🦾 行动

感知：收到指令和环境信息
思考：LLM 推理，决定"现在该干啥"
行动：调用工具执行（查数据库、发邮件、写文件……）

💡 例子：你让我查天气

  • ① 感知：你说"深圳今天会不会下雨"
  • ② 思考：我需要调用天气工具查深圳
  • ③ 行动：我用工具查了，把结果回给你

这是最简单的 Agent 循环。

❸不是所有 Agent 都要有 UI
Agent 可以没有对话框，后台默默干活，主动找你而不是等你去问。
  • 🌙 凌晨 3 点爬起来检查服务器磁盘 → Agent
  • 📬 收到新邮件自动归档回复 → Agent
  • 📰 每天 9 点推行业日报 → Agent
关键区别：LLM 等你去问它；Agent 会主动来找你。
DAY 2

LLM 是怎么"思考"的？

别怕术语——超级自动补全 + 打草稿就是真相
❶LLM 本质上是超级自动补全
核心原理：输入词块，预测下一个最可能出现的词，仅此而已。
输入一串 token（词块），预测下一个最可能的词
输入：床前明____
预测：月（高概率）→ 光（高概率）→ ...

"床前明月光" → LLM 不是在"理解"诗，是在算概率。

LLM 不是真的"会思考"，它是在做排列组合的概率游戏。
❷为什么 LLM 看起来像会思考？
量变到质变，参数暴涨后概率组合产生了"语感"。
模型参数规模能力阶段
GPT-215 亿写句子都卡顿
GPT-31750 亿能写文章了
GPT-4~1.8 万亿能写代码、过律师考试
就像你从只在中文里学概率 → 突然有了"语感"。
❸"推理"= 把中间步骤写下来
Chain-of-Thought：让 LLM 打草稿，一步步写过程，正确率翻倍。

例子：17 × 24

普通 LLM：

"17 × 24 = 408"

带推理（Chain-of-Thought）：

17 × 24 = 17 × 20 + 17 × 4
         = 340 + 68
         = 408
这就是所有"推理模型"（o1、DeepSeek-R1 等）的基本原理——不是换了更好的大脑，只是让它"先想清楚再写答案"。
DAY 3

工具调用（Function Calling）

Agent 怎么用工具干活？LLM 每次只做二选一：说话还是动手
❶LLM 交互是"二选一"
每次回复要么说人话，要么返回工具调用请求，由系统执行。
  • 💬 直接回复文本（像普通聊天）
  • 🛠️ 请求调用工具（告诉系统：我要用这个工具，参数是这些）

例子：你问"深圳天气怎么样？"

没有工具 → "抱歉，我没有实时数据。"

有工具 → LLM 返回：

{
  "function": "get_weather",
  "params": {"city": "深圳"}
}

系统执行后把结果塞回去给 LLM，组织成自然语言回复你。

❷例子：点外卖的完整流程
从"帮我点个披萨"到下单成功，背后跑了搜索和下单两轮工具调用。
  1. Agent 收到 → 调用 search_pizza_nearby
  2. 工具返回：「必胜客 + 超级至尊 ¥79」
  3. Agent 确认 → 调用 place_order
  4. LLM 告诉你下单成功
你全程感觉就是在聊天。实际上背后跑了一堆工具调用。
❸工具是 Agent 的能力边界
Agent 能做什么，取决于配了什么工具。
没有的工具Agent 就做不到
🌤️ 天气工具不会查天气
📧 邮件工具不会发邮件
🗄️ 数据库工具不会查用户信息
💳 支付工具不会付款
Agent 能做什么，取决于你给它配了什么工具。
DAY 4

Memory：Agent 怎么"记住"你？

LLM 天生没有记忆——Agent 的"记住"是存储 + 检索的伪装技巧
❶LLM 天生没有记忆
每次对话是把历史重新塞给 LLM，不是"记住"，是"重读一遍"。
  • 💬 10 条消息 ≈ 3000 字
  • 🗣️ 1000 条消息 ≈ 30 万字
  • ⚠️ 上下文窗口有限，超了就忘了
Agent 的"记忆"本质是存储 + 检索策略。不是真的记得你，只是每次帮你把回忆整理好再拿出来。
❷三种记忆层级
短期靠上下文，中期靠文件/向量库，长期靠数据库存用户画像。
层级存什么怎么存
短期当前对话上下文窗口
中期关键信息总结 + 文件/向量库
长期用户画像结构化数据库
❸记忆技巧：存什么比怎么存重要
好的记忆要筛选——只存有价值信息，不存废话和完整日志。
判断内容理由
✗"今天巴黎下雨了"一次性，没价值
✓"用户下周要去巴黎出差"安排日程用
✗完整对话日志太占上下文
✓对话摘要一天一总结够用不占地方
一个"记住你是谁"的 Agent 和一个每次都要重新自我介绍的 Agent，体验天差地别。
